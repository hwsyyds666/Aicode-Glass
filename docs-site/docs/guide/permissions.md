# 工具授权

AI 要执行命令、写文件之前需要你授权。本页管理已经保存下来的授权规则，入口在「设置 → 工具授权」。

## 规则的来源

对话中 AI 请求调用需要确认的工具时会弹出授权面板。可用选项取决于操作类型：普通工具可单次允许；符合条件的工具也可选择始终允许；删除命令只允许拒绝、交给 AI 审查或单次允许，不能记住授权。

拒绝只拒绝当前调用，不会创建允许规则。命令授权主要由下方的授权挡位与高危规则决定；命令不能通过「始终允许」记忆来绕过高危检查。

另外系统有一份内置白名单：少量完全无害、只读、不派生子进程的命令（`ls`、`pwd`、`cat`、`grep`、`ps`、`top`、`git status` 等）不弹窗直接放行。

## 命令授权挡位与 AI 审查

「设置 → 工具授权」里的命令授权挡位决定 shell 命令如何处理：

- **规则拦截**：命中高危规则的命令会请求你确认，其余命令按现有规则执行。
- **自主执行**：只读命令，以及工作区内受限的常规构建、测试、lint 命令由规则直接放行；其它命令由独立审查器结合最新任务、近期对话、执行理由、命令、工作目录和执行环境判断。审查通过后会自动执行，展开工具卡片可查看审查依据；明确危险的命令会被拒绝并把原因交还给 AI，拿不准、审查失败或超时则弹窗请你决定。等待时间可在此页设置为 10、15 或 20 秒。
- **完全权限**：普通命令直接执行；删除命令仍逐次授权，根目录、系统关键目录和工作区根目录本身始终硬拦截。

调用 `Bash`、Shizuku 或后台终端执行命令时，AI 必须附上执行理由。缺少理由的命令会被拒绝；审查器会独立核对理由与命令效果，不能只凭理由放行。工作区外删除、强制推送、提权、读取凭据以及向外部上传数据等高风险动作不会自动放行。审查超时或服务异常时会转人工确认，不会默认放行。

例外：`Shizuku` 工具（以 adb shell 身份操作宿主 Android 系统）属高危，默认逐次弹窗且不支持「始终允许」，也不适用内置白名单；通用安全拦截开关开启时它不再逐次弹窗，详见 [Shizuku 工具](/guide/shizuku)。

## 多会话并行时的授权

多个会话（含子代理）同时工作时，每个会话可以各自挂起一个授权请求，互不阻塞：

- 授权弹窗顶部会标注**发起该请求的会话标题**（如「会话「重构登录模块」」），可明确区分弹窗属于哪个会话。
- 弹窗在任意会话界面都会展示，处理完自动切到下一个待授权请求。
- 侧边栏会话列表里，**正在等待授权**的会话行左侧指示灯是**橙色常亮**（执行中是绿色脉冲）。据此可以发现被挂起等待授权的后台会话，点进去处理。

## 删除安全边界

删除命令始终单独审查，不受「完全权限」或关闭通用安全拦截影响。普通目标可由用户拒绝、先交 AI 审查，或核对后单次允许；AI 无法确认或判定有风险时会回到人工确认。删除授权不提供「始终允许」。

根目录、用户主目录、系统关键目录以及当前工作区根目录本身是硬拦截目标，任何授权挡位、AI 审查或单次允许都不能覆盖。无法静态解析的脚本、命令替换、通配符或输入流目标会标注为不确定/高风险，并要求用户明确决定。

## 关于「禁止」规则

授权弹窗里没有「禁止」这个选项（拒绝只影响单次），所以正常使用不会产生禁止规则。

禁止规则目前只能手动编辑配置文件产生：项目规则写在 `<项目根>/.aicode/permissions.json`，全局规则写在 `~/.aicode/permissions.json`。手工编辑保存后 App 会在几秒内自动检测并刷新页面，规则立即生效。

配置文件格式：

```json
{
  "permissions": {
    "allow": ["Bash(git pull)", "writeFile"],
    "deny": ["Bash(rm -rf /)"]
  }
}
```

::: tip 全局禁止优先于项目允许
`deny` 里的规则会挡掉同名的 `allow` 规则。例如全局禁止了 `Bash(rm -rf /)`，那么任何项目都不能放行这条命令。如需额外的安全兜底，可在全局 `deny` 里添加规则。
:::
